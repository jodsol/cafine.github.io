## 간략한 프로필

- 웹과 사람을 연결하는 개발자 조혜형입니다.
- 대학에서 산업정보시스템공학을 공부하며 웹 개발을 시작했습니다.
- 개발자 커뮤니티와 공연 예매 서비스 같은 팀 프로젝트를 거치며 프론트엔드 개발의 재미를 알게 됐습니다.
- 비디오 스트리밍 회사에서 React 기반 웹 서비스와 SDK를 만들다가, 필요에 따라 Spring 백엔드와 배포 인프라까지 다루게 됐습니다.
- 이후 공간 데이터와 지도 서비스를 만드는 회사에서 Three.js와 Unity를 활용한 3D 그래픽스 개발을 경험했습니다.
- 프론트엔드로 시작했지만, 문제를 해결하는 데 필요하다면 백엔드와 인프라도 자연스럽게 넘나듭니다.
- 지금도 새로운 기술을 배우고, 느린 것을 빠르게 만들고, 복잡한 것을 관리하기 쉽게 만드는 일을 좋아합니다.

## 개발할 때 중요하게 생각하는 것

- 사용자에게 보이는 화면뿐 아니라 서비스가 배포되고 운영되는 과정까지 함께 고민합니다.
- 기획자, 디자이너, 백엔드 개발자 사이에서 요구사항을 개발 가능한 형태로 정리하는 일을 중요하게 생각합니다.
- 반복되는 설정과 작업은 자동화하고, 복잡하게 얽힌 코드는 읽기 쉬운 구조로 개선하려고 합니다.
- 메모리 누수나 렌더링 병목처럼 눈에 잘 보이지 않는 문제를 찾아 해결하는 것을 즐깁니다.
- 익숙하지 않은 분야라도 문제 해결에 필요하다면 일단 공부하고 부딪쳐 봅니다.

## 밥벌이를 위해 주로 다루는 분야

- React, Next.js, TypeScript 기반의 프론트엔드 애플리케이션
- Three.js와 Unity를 활용한 실시간 3D 그래픽스
- 대용량 공간 데이터와 다수의 오브젝트 렌더링 최적화
- 비디오 스트리밍, 비디오 플레이어, 채팅 SDK와 같은 미디어 서비스
- Node.js, NestJS, Spring Boot 기반의 백엔드 서비스
- 모노리포 구성과 공통 라이브러리 및 개발 환경 관리
- 테스트, 코드 리뷰, CI/CD를 포함한 지속 가능한 개발 프로세스

## 성능 문제를 만나면 주로 하는 일

- Chrome DevTools로 메모리 누수와 렌더링 병목을 추적합니다.
- 사용이 끝난 Three.js 리소스가 제대로 해제됐는지 집요하게 확인합니다.
- Draw Call이 많으면 Merged Mesh, GPU Instancing, LOD 같은 방법을 고민합니다.
- 대용량 에셋은 압축하고, 필요한 시점에 필요한 만큼만 불러오도록 구성합니다.
- 결국 중요한 것은 화려한 기술 이름보다 사용자가 느끼는 속도라고 생각합니다.

## 밥벌이를 위해 자연스럽게 다루게 된 분야

- AWS의 EC2, S3, CloudFront, RDS, ALB 등 기본적인 서비스
- Jenkins, GitHub Actions를 활용한 빌드와 배포 자동화
- Terraform을 활용한 인프라 설정 관리
- Redis를 활용한 데이터 캐싱
- Docker와 Nginx를 활용한 서비스 운영
- MySQL, PostgreSQL, MongoDB 등 상황에 따라 달라지는 데이터베이스
- 프론트엔드 개발자로 시작했지만 이제는 서버 로그도 제법 자연스럽게 봅니다.

## 주로 사용하는 기술

- **Front-End:** TypeScript, JavaScript, React, Next.js, Gatsby
- **Graphics:** Three.js, Unity
- **Back-End:** Node.js, NestJS, Spring Boot
- **Data:** Redis, MySQL, PostgreSQL, MongoDB
- **DevOps:** AWS, Jenkins, GitHub Actions, Docker, Terraform, Nginx
- **State Management:** Redux Saga, Jotai, Zustand, MobX
- **Test:** Jest, React Testing Library, MSW

## 그 외

- 새로운 기술에 대한 거부감이 적고, 필요하면 빠르게 배워서 적용하는 편입니다.
- 프론트엔드와 백엔드 사이에 선을 긋기보다 서비스 전체를 이해하려고 합니다.
- 그래픽스와 비디오처럼 성능과 사용자 경험이 직접 맞닿는 분야에 관심이 많습니다.
- 언젠가 더 복잡한 그래픽스 문제를 더 단순한 코드로 해결하고 싶습니다.
